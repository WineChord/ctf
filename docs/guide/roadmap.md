# 学习路线

CTF 覆盖的技术面很宽。更有效的路线不是同时学习所有分类，而是先建立共同基础和解题闭环，再选择一个主方向深入，同时保留跨分类迁移能力。

## 阶段 0：工作环境与边界

开始之前先建立三个习惯：

1. 只操作自己拥有或明确授权的目标；
2. 使用虚拟机、容器或专用用户隔离实验；
3. 保存原始题目附件，记录哈希，所有修改在副本上进行。

配套阅读：

- [合法边界与实验安全](lab-safety.md)
- [工具与工作台](tooling.md)
- [解题方法](methodology.md)

## 阶段 1：共同基础

### Linux 与命令行

需要熟悉：

- 文件、目录、权限、管道和重定向；
- 进程、信号、环境变量和文件描述符；
- `file`、`strings`、`xxd`、`grep`、`find`、`tar` 等基础工具；
- Shell 引号、退出码和标准输入输出。

### 编程与数据表示

Python 适合快速处理字节、协议和数学；C/C++ 有助于理解内存、整数和二进制。至少掌握：

- 二进制、十六进制、补码和端序；
- ASCII、Unicode、UTF-8、Base64；
- 字节串与文本的区别；
- 正则表达式、文件读写与网络基础；
- 哈希、压缩、序列化与常见容器格式。

入口：[字节、编码与端序](../fundamentals/bytes-encoding.md)。

### 网络与 Web

理解 TCP/IP 分层、DNS、端口、HTTP 请求/响应、Cookie、同源策略和代理。很多“工具问题”本质上是没有分清浏览器、代理、服务端和网络分别看到了什么。

## 阶段 2：选择一个主方向

| 方向 | 优先基础 | 第一批目标 |
| --- | --- | --- |
| [Web](../web/index.md) | HTTP、浏览器、后端与数据库 | 能手工解释一次完整请求的数据流 |
| [Pwn](../pwn/index.md) | C、汇编、ELF、Linux 进程 | 能在调试器中连接源码、指令、寄存器和栈 |
| [逆向](../reverse/index.md) | 汇编、编译、文件格式 | 能从控制流和数据流恢复关键算法 |
| [密码](../crypto/index.md) | 数论、概率、Python 大整数 | 能区分原语、协议、参数和实现问题 |
| [取证](../forensics/index.md) | 文件系统、网络、时间线 | 能保全证据并从多种视角交叉验证 |
| [Misc](../misc/index.md) | 自动化与快速学习 | 能把陌生格式拆成可检验的小问题 |

建议用大约 70% 时间投入主方向，30% 时间维护共同基础和邻近分类。Pwn 与逆向、Web 与取证、密码与编程经常互相借力。

## 阶段 3：从题型到原理

完成几道同类题后，不要只继续刷相似输入。开始追问：

- 这个现象属于哪一层？
- 哪个安全边界或程序不变量被破坏？
- 工具输出是直接证据还是启发式判断？
- 保护机制改变后，原路径哪里失效？
- 能否用一个更小样本独立复现？
- 防御端应该在哪一层阻断或检测？

这一阶段的目标，是从“知道命令”转向“能预测系统行为”。

## 阶段 4：比赛化训练

### 赛前

- 固定虚拟机、工具版本和目录结构；
- 准备离线文档与常用脚本；
- 确认代理、时区、磁盘空间和快照；
- 列清赛事规则、共享范围和禁止动作。

### 赛中

- 先保存题面、附件和哈希；
- 快速分类，但允许随证据调整；
- 每条假设配一个最小实验；
- 命令、关键输出和失败路径随手记录；
- 自动化脚本先在本地小样本上验证。

### 赛后

- 在不看临时命令历史的情况下重新复现；
- 删除偶然有效但无法解释的步骤；
- 对照官方或优秀 Writeup 补全缺失原理；
- 把新知识连接到已有专题，而不是只保存题号。

## 如何判断真正掌握

一个知识点至少通过四层检验：

1. **识别**：能从证据定位候选层和题型；
2. **解释**：能说清被破坏的假设或使用的数学性质；
3. **复现**：能在干净授权环境中独立重做；
4. **迁移**：输入、保护或协议变化后，能判断原路径是否仍成立。
