# Writeup 写作模板

一篇可复用 Writeup 应把事实、推断、实验和最终结论分开。读者不应依赖作者的 Shell 历史或未说明环境才能复现。

## 1. 基本信息

- 赛事 / 靶场；
- 题目名称与分类；
- 公开题目链接；
- 允许公开的日期；
- 测试范围和环境；
- 关键标签。

若题目仍在进行、规则禁止公开或附件不可再分发，不发布正文和附件。

## 2. 环境

记录：

- 操作系统与架构；
- 运行时和关键工具版本；
- 容器、虚拟机或本地依赖；
- 本地与远程差异；
- 时区、随机种子等可影响结果的条件。

## 3. 原始证据

列出可公开附件的：

- 文件名；
- 大小；
- SHA-256；
- 初步文件类型；
- 来源与获取时间。

不直接提交真实 Token、Cookie、Flag、账号、代理历史或未脱敏日志。

## 4. 题目重述

去掉故事包装，用一两句话说明：

- 输入或可观察对象是什么；
- 目标是什么；
- 有哪些限制；
- 成功判定是什么。

## 5. 第一轮观察

按证据列出，不急于下结论：

| 观察 | 证据位置 | 当前解释 | 置信度 |
| --- | --- | --- | --- |
|  |  |  |  |

扩展名、工具标签、错误消息和反编译变量名都应视为线索，而不是事实本身。

## 6. 假设与实验

对每个关键假设：

1. 假设是什么；
2. 为什么提出；
3. 最小实验如何设计；
4. 输入和输出是什么；
5. 结果支持还是反驳；
6. 下一步如何变化。

保留真正影响路线选择的失败实验，删除没有信息量的重复尝试。

## 7. 原理

解释被使用或破坏的：

- 协议语义；
- 解析规则；
- 安全边界；
- 程序不变量；
- 机器模型；
- 数学性质；
- 文件格式。

必要时使用图、公式、内存布局或状态机。工具命令放在原理之后服务于解释。

## 8. 稳定复现

提供：

- 最小依赖；
- 从原始附件开始的步骤；
- 完整脚本；
- 超时、重试和输入约束；
- 预期关键输出；
- 失败时的诊断信号。

远程地址、凭据和 Flag 使用明确占位符。示例命令优先指向 `127.0.0.1` 或题目官方公开地址。

## 9. 交叉验证

至少说明一种独立确认：

- 静态与动态结果一致；
- 公式与小规模枚举一致；
- 两个方向的转换互逆；
- 输出同时满足格式、语义和校验；
- 网络行为与本地服务实现一致。

## 10. 失败路径

记录：

- 为什么最初方向看似合理；
- 哪条证据推翻它；
- 工具或环境产生了什么误导；
- 下次可以更早做哪个低成本实验。

## 11. 条件变种

改变一个条件：

- 版本；
- 编译器或架构；
- 保护机制；
- 输入长度与字符集；
- 缓存、并发和随机性；
- 密码参数；
- 文件或协议解析器。

说明原解法哪一步失效，以及应转向哪个新模型。

## 12. 防御视角

回答：

- 根因如何修复；
- 应在哪一层验证、隔离或授权；
- 哪些日志或告警可检测；
- 单元测试和集成测试如何覆盖；
- 哪些缓解只降低影响但没有消除根因。

## 13. 发布检查

- [ ] 赛事和平台允许公开；
- [ ] 没有未结束比赛的 Flag；
- [ ] 没有凭据、Cookie、私钥、个人信息或私有地址；
- [ ] 附件允许再分发；
- [ ] 所有命令都在授权范围内；
- [ ] 事实、推断和未验证内容清楚区分；
- [ ] 脚本可从干净环境运行；
- [ ] 外部参考链接到原始或权威来源；
- [ ] 内容没有依赖未公开的对话或内部信息。
