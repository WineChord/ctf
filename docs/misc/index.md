# Misc 知识地图

Misc 不是“没有分类”，而是强调快速建模、跨领域迁移和自动化。题目可能涉及编程、协议、Jail、OSINT、二维码、音频、游戏、区块链或自定义系统。

## 第一轮分类

先问：

- 输入是文本、字节、图片、音频、流量还是交互协议；
- 是否存在标准格式或魔数；
- 任务是还原、搜索、优化、模拟还是绕过限制；
- 数据规模暗示暴力、算法还是数学；
- 是否能离线复现；
- 哪些行为受赛事规则限制。

不要因题目标签是 Misc 就放弃已有知识地图。

## 编程与算法

常见能力：

- 解析不规则输入；
- 图搜索、动态规划和组合枚举；
- 状态机与模拟；
- 约束求解；
- 并行和批处理；
- 与远程交互同步。

先写小规模正确实现，再优化；保留本地参照答案做随机对拍。

## Jail 与受限执行

Jail 题研究语言、解析器、运行时和过滤器之间的边界。分析时：

1. 明确输入经过哪些解析阶段；
2. 区分字符过滤、语法限制和运行时权限；
3. 最小化每个表达式；
4. 在本地相同版本复现；
5. 记录可用对象、内建和副作用；
6. 只在题目提供的隔离环境中测试。

版本差异会改变语法、对象图和沙箱行为。

## OSINT

公开来源情报强调来源、时间和交叉验证：

- 记录原始 URL、发布时间和访问时间；
- 区分原始来源与转载；
- 图片地理定位结合地标、光照、语言和地图；
- 元数据可能被删除或伪造；
- 搜索结果会随地区、时间和个性化变化；
- 不收集或发布与题目无关的个人信息。

OSINT 题的授权不等于可以骚扰、联系或曝光真实个人。

## 协议与自动化

远程交互先手工记录一轮：

```text
连接建立 → 欢迎信息 → 题目数据 → 本地计算 → 响应 → 下一轮
```

脚本需要处理：

- 消息边界；
- 编码与换行；
- 超时与断线；
- 轮次和状态；
- 错误恢复；
- 服务端速率限制。

TCP 是字节流，一次 `recv` 不保证等于一条完整消息。

## 图像、音频与二维码

先确认：

- 文件格式和元数据；
- 尺寸、色彩空间、通道和帧；
- 是否有附加数据；
- 统计分布和异常区域；
- 变换是否可逆；
- 工具输出能否回到原始数据验证。

图像“看不见”不代表没有数据，工具“识别到”也不等于结果正确。

## 区块链题

需要区分：

- 链上状态与本地模拟；
- 交易、调用和日志；
- 整数、精度和单位；
- 权限、重入和状态更新顺序；
- 共识层与合约层；
- 题目私链与真实主网。

只使用题目提供的本地或测试环境，不向真实网络发送未经确认的交易。

## 复盘重点

Misc 最值得记录的是：

- 陌生对象如何被识别；
- 哪个已有知识发生了迁移；
- 哪些低成本实验迅速排除了方向；
- 自动化的稳定判定条件是什么；
- 如果重新分类，它应连接到哪个专题。
